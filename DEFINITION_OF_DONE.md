# Definition of Done

This document defines when a report in this repository is considered complete.

## A report is done when

- [ ] The report states its purpose, audience, and scope up front.
- [ ] The report reflects the current state of the repository, not assumptions or outdated findings.
- [ ] Every material claim is backed by evidence such as source files, tests, issues, pull requests, standards, or reproducible observations.
- [ ] Findings are organized clearly and use the repository's severity model where relevant:
  - Critical
  - High
  - Medium
  - Low
- [ ] Accessibility impacts are identified in terms of WCAG 2.2 AA and project accessibility policy when the report discusses UI, content, or workflows.
- [ ] Recommendations are specific, actionable, and tied to the problem they address.
- [ ] The report distinguishes confirmed findings, assumptions, open questions, and follow-up work.
- [ ] Any referenced commands, checks, or test results have been run or explicitly marked as pending verification.
- [ ] The writing uses plain, respectful, inclusive language and is understandable by non-specialist readers.
- [ ] The Markdown structure is accessible and readable:
  - descriptive heading hierarchy
  - clear lists and tables
  - meaningful link text
  - no reliance on colour alone
- [ ] The report includes a concise summary of what is working, what is not, and what should happen next.
- [ ] The report can be handed to a maintainer and used to create issues or implementation work without needing extra interpretation.

## Minimum review checklist

- [ ] Facts were checked against the current repository contents.
- [ ] Cross-references and links work.
- [ ] Suggested next steps align with the project's static-first, accessibility-first, and vanilla JavaScript constraints.
- [ ] No recommendation introduces a known security, privacy, or accessibility regression.
- [ ] Any limitations, unknowns, or external dependencies are explicitly called out.

## Done means

The report is complete when it is accurate, evidence-based, accessible, actionable, and ready to support decisions or follow-on implementation work.
